## 6.5.1 文件描述符与文件偏移量

### 例题1：同一文件打开两次

假设 `test.txt` 中只有 `test`，执行下面的程序后，文件内容会变成什么？程序会输出什么？（假设打开和读取均成功。）

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    int fd1, fd2;
    char c;
    fd1 = open("test.txt", O_RDONLY, 0);
    fd2 = open("test.txt", O_RDONLY, 0);
    read(fd1, &c, 1);
    read(fd2, &c, 1);
    printf("fd1=%d,fd2=%d,c=%c\n", fd1, fd2, c);
    return 0;
}
```

<details class="example-answer">
<summary>答案</summary>

文件内容仍为 `test`。程序以只读方式打开文件，只进行了读取操作，没有修改文件内容。

若标准输入、标准输出和标准错误分别占用文件描述符 `0`、`1`、`2`，且没有其他文件描述符被占用，则输出为：

```text
fd1=3,fd2=4,c=t
```

两次 `open` 分别建立独立的打开文件状态，各自的文件偏移量初始都为 `0`。因此，两次 `read` 都读取第一个字符 `t`，读取后各自的偏移量均为 `1`，变量 `c` 最终为 `t`。

文件描述符的具体数值取决于进程中已有描述符的占用情况。

</details>

## 6.5.2 文件 I/O 综合分析

### 例题2：fopen、fread 与内核 I/O 处理过程

#### （1）题目代码

课件以 IA-32 Linux 为例，用户程序 P1 中有以下片段：

```c
int len, n, buf[BUFSIZ];
FILE *fp;
/* …… */
fp = fopen("bin_file.txt", "r");
n = fread(buf, sizeof(int), BUFSIZ, fp);
/* …… */
```

课件第 12 页代码图把第二个调用写成 `fread` 参数形式的 `read`，而第 14 页标题与流程明确使用 fread；此处据对应流程统一为 `fread`。

#### （2）已知条件

文件 bin_file.txt 已存在于磁盘上，含有足够多的数据，此前未被读取过。

#### （3）问题与答案

#### 第1问：fopen 的调用过程

执行 fopen 所在语句时，从用户程序执行到内核 I/O 软件执行的过程怎样？画出函数调用关系，并用自然语言描述。

<details class="example-answer">
<summary>答案</summary>

![图 6.25 用户程序调用 fopen 函数到内核 I/O 软件执行的过程](/images/chapter06/fopen-kernel-execution.png)

用户程序调用 C 标准 I/O 库函数 `fopen`，`fopen` 再调用 `open` 封装函数。这些函数都在用户空间、用户态下执行。

`open` 封装函数通过陷阱指令 `int $0x80` 进入内核，CPU 从用户态切换到内核态，由系统调用处理程序 `system_call` 将请求分派给 `sys_open` 服务例程，完成打开文件所需的内核操作。

内核返回文件描述符后，`fopen` 建立并初始化相应的文件流管理信息，将 `FILE *` 返回给用户程序，赋给 `fp`。

</details>

#### 第2问：fread 的调用过程

执行 fread 所在语句时，从用户程序执行到内核 I/O 软件执行的过程怎样？画出函数调用关系，并用自然语言描述。

<details class="example-answer">
<summary>答案</summary>

![图 6.26 用户程序调用 fread 函数到内核 I/O 软件执行的过程](/images/chapter06/fread-kernel-execution.png)

用户程序调用 C 标准 I/O 库函数 `fread`。当文件流的缓冲区中没有足够的数据时，`fread` 调用 `read` 封装函数，请求从底层读取数据。

`read` 封装函数通过 `int $0x80` 进入内核，由 `system_call` 将请求分派给 `sys_read` 服务例程。读取完成后，返回用户空间，由 `fread` 将所需数据交给用户程序的 `buf`，并将成功读取的完整数据项数返回给 `n`。

若文件流缓冲区已有足够的数据，`fread` 可以直接使用这些数据，不必每次都进入内核。

</details>

#### 第3问：底层内核 I/O 软件的处理过程

执行 fread 时，通过陷阱指令进入内核后，底层内核 I/O 软件的大致处理过程怎样？

<details class="example-answer">
<summary>答案</summary>

大致经过“检查读请求 → 查找文件数据 → 必要时访问磁盘 → 返回数据”的过程：

1. **检查请求并定位文件**：`sys_read` 检查文件描述符、读权限和用户缓冲区等参数，通过进程的文件描述符表找到对应的打开文件状态，取得当前文件偏移量及文件相关信息。
2. **查找所需数据**：通过虚拟文件系统调用具体文件系统的读操作，根据文件偏移量确定要读取的文件数据，检查这些数据是否已在内核缓存中。
3. **需要时启动磁盘读取**：若缓存未命中，文件系统确定数据所在的磁盘块，向块设备层和磁盘驱动程序提交读请求。驱动程序设置设备控制器，通常通过 DMA 将磁盘数据传送到主存中的内核缓冲区；等待数据期间，请求进程可以阻塞，CPU 转去执行其他进程。
4. **处理完成通知**：磁盘传送完成后，通常通过中断通知 CPU。中断服务程序及后续处理更新 I/O 状态，并唤醒等待数据的进程。
5. **交付数据并返回**：内核把数据复制到 `read` 所指定的用户空间缓冲区，更新文件偏移量，返回实际读取的字节数，随后恢复用户态执行。标准 I/O 库再完成缓冲管理，把请求的数据交给程序的 `buf`。

题目说明文件此前未被读取过，通常按所需数据尚未进入内核缓存、需要访问磁盘来分析；实际系统中是否访问磁盘，仍取决于缓存是否命中。若已命中缓存，就可以省去磁盘读取及相应的等待过程。

</details>
