## 6.2.1 标准 I/O 与系统级 I/O

### 1. 两类函数

| 类别 | 课件示例 | 主要接口对象 |
|------|----------|--------------|
| 标准 I/O 库函数 | fread、fwrite、printf 等 | 文件流 FILE |
| 系统级 I/O 函数 | read、write 等 | 文件描述符 |

### 2. 标准 I/O 库函数与系统级 I/O 函数的优缺点

#### （1）可移植性

**标准 I/O 库函数**：由 C 标准规定接口，可移植性好，便于程序在不同操作系统之间移植。

**系统级 I/O 函数**：依赖操作系统提供的接口，跨不同操作系统的可移植性较差；遵循 POSIX 标准的系统之间通常具有较好的兼容性。

#### （2）效率

**标准 I/O 库函数**：通常使用用户空间缓冲区，可将多次小量读写合并，减少系统调用次数，提高效率；但也会增加缓冲管理和数据复制的开销。

**系统级 I/O 函数**：不提供标准 I/O 库这一层的缓冲，频繁进行小量读写时，系统调用开销较大；合理使用较大的读写缓冲区，也能获得较高效率。

#### （3）功能

**标准 I/O 库函数**：提供按字符、按行、按块以及格式化输入输出等功能，使用方便；但不能覆盖所有底层 I/O 控制需求。

**系统级 I/O 函数**：直接操作文件描述符，适用于普通文件、设备、管道和套接字等，可配合其他系统接口进行底层控制；但格式转换、按行处理等通常需要程序自行实现。

#### （4）问题

**标准 I/O 库函数**：缓冲可能使输出不能立即显示或写出，必要时需使用 `fflush` 刷新输出流；与系统级 I/O 混用时，还需注意缓冲内容和文件位置的一致性。

**系统级 I/O 函数**：一次 `read` 或 `write` 实际传送的字节数可能少于请求数，程序需要检查返回值，并按需处理短读、短写和中断，编程较复杂。

### 3. 文件的基本操作

创建文件、打开文件、设置读写位置、读写文件，使用结束后关闭文件。

### 4. 课件文件复制示例

```c
void filecopy(FILE *infp, FILE *outfp) {
    ssize_t len;
    while ((len = fread(buf, 1, BUFSIZE, infp)) > 0) {
        fwrite(buf, 1, len, outfp);
    }
}
```

按课件保留片段，buf 和 BUFSIZE 由外部上下文提供。该片段用于展示 fread、fwrite 的组合。

## 6.2.2 系统级 I/O 函数

### 1. 主要操作

| 函数 | 作用 |
|------|------|
| creat | 创建文件 |
| open | 打开文件 |
| read | 读取数据 |
| write | 写入数据 |
| lseek | 设置文件读写位置 |
| stat / fstat | 获取文件状态 |
| close | 关闭文件 |

课件第 4 页将创建函数写成 `create`，此处按接口名称整理为 `creat`。

## 6.2.3 标准I/O库函数

### 1. 输出缓冲属性

| 缓冲方式 | 宏 | 基本含义 |
|----------|----|----------|
| 全缓冲 | `_IOFBF` | 缓冲区满等条件下输出 |
| 行缓冲 | `_IOLBF` | 遇到换行等条件时输出 |
| 无缓冲 | `_IONBF` | 不使用标准库的相应缓冲 |

### 2. 标准文件流

- `stdin`：标准输入。
- `stdout`：标准输出。
- `stderr`：标准错误。
