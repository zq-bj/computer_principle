## 3.5.1 AT&T 格式是什么

### 1. 基本概念

AT&T 格式是 x86 汇编语言的一种书写格式，GNU 汇编器 `as` 默认采用这种格式，GCC 生成的 x86 汇编代码也常使用它。

Intel 格式是另一种书写格式。**同一条机器指令可以用两种格式表示，书写规则不同，执行功能相同。** 本节以 IA-32 整数指令为例。

```asm
# AT&T 格式
movl $5, %eax
```

对应的 Intel 格式为：

```asm
mov eax, 5
```

两者都表示把整数 5 传送到 EAX。

## 3.5.2 AT&T 与 Intel 格式的区别

### 1. 常用规则对照

| 比较项 | AT&T 格式 | Intel 格式 |
|------|------|------|
| 常见双操作数指令的顺序 | 源操作数在前，目的操作数在后：`movl %eax, %ebx` | 目的操作数在前，源操作数在后：`mov ebx, eax` |
| 寄存器 | 名称前加 `%`，如 `%eax` | 直接写名称，如 `eax` |
| 立即数 | 前加 `$`，如 `$5` | 直接写数值，如 `5` |
| 操作数大小 | 指令后缀表示：`b` 为 8 位、`w` 为 16 位、`l` 为 32 位 | 可由寄存器判断；必要时在内存操作数前写 `BYTE PTR`、`WORD PTR`、`DWORD PTR` |
| 内存操作数 | 用圆括号组合地址，如 `8(%ebp)` | 用方括号表示，如 `[ebp+8]` |
| 基址加变址寻址 | `8(%ebp,%ecx,4)` | `[ebp+ecx*4+8]` |
| 符号扩展传送 | 用两个大小后缀，如 `movsbl %al, %edx` | 用 `movsx`，如 `movsx edx, al` |
| 零扩展传送 | 用两个大小后缀，如 `movzbl %al, %edx` | 用 `movzx`，如 `movzx edx, al` |

<span style="color:#c0392b; text-decoration:underline">**AT&T：先源后目的，寄存器加 %，立即数加 $，大小看指令后缀，访存地址看圆括号。**</span>

## 3.5.3 AT&T 格式怎么用

### 1. 格式

| 情况 | 格式 |
|------|------|
| 普通双操作数指令 | `指令名(操作数大小) src, dst` |
| 扩展传送指令 | `指令前缀(源操作数大小)(目的操作数大小) src, dst` |

| 组成部分 | 含义 |
|------|------|
| 指令名或前缀 | 要执行的操作，如 `mov`、`add`、`sub`，或扩展传送前缀 `movs`、`movz` |
| 操作数大小 | 大小后缀：`b` 表示 8 位，`w` 表示 16 位，`l` 表示 32 位；普通形式写一个，扩展传送按源、目的顺序写两个 |
| src | 源操作数，提供数据，可以是立即数、寄存器或内存，具体取决于指令 |
| dst | 目的操作数，通常接收结果，可以是寄存器或内存，具体取决于指令 |
| 逗号 | 分隔 src 和 dst，源在前，目的在后 |

括号内是后缀的占位说明，实际书写时直接拼接，不写括号，例如 `movl`、`movsbl`。

### 3. 操作数大小怎么填

本节使用 IA-32 整数操作数，大小后缀如下：

| 大小 | 后缀 | 寄存器示例 | 指令示例 |
|------|:------:|------|------|
| 8 位 | `b` | AL、BL、AH | `movb %al, %bl` |
| 16 位 | `w` | AX、BX、CX | `movw %ax, %bx` |
| 32 位 | `l` | EAX、EBX、ECX | `movl %eax, %ebx` |

**先看变量类型、寄存器名称或题目条件，确定数据位数，再填写后缀。** 立即数的数值大小不决定操作位数，例如把 5 传入 EAX 要写 `movl $5, %eax`，因为目的寄存器是 32 位。

普通 `mov` 的两边位宽相同，只写一个后缀；扩展传送写两个后缀，分别表示源和目的的位宽：

| 源位数 → 目的位数 | 后缀组合 | 符号扩展 | 零扩展 |
|------|:------:|------|------|
| 8 → 16 | `bw` | `movsbw %al, %bx` | `movzbw %al, %bx` |
| 8 → 32 | `bl` | `movsbl %al, %ebx` | `movzbl %al, %ebx` |
| 16 → 32 | `wl` | `movswl %ax, %ebx` | `movzwl %ax, %ebx` |

若只需要保留较宽寄存器的低位，则直接使用其低位名称，例如用 `movb %al, %bl` 复制 EAX 的低 8 位，不能写成 `movb %eax, %bl`。

### 4. src、dst 有哪些形式，怎么用

#### （1）三种常见操作数

| 操作数形式 | 怎么写 | 表示什么 | 能否作为 src | 能否作为 dst |
|------|------|------|:------:|:------:|
| 立即数 | `$5`、`$0x80`、`$-1` | 数值本身 | 可以，取决于指令 | 不可以 |
| 寄存器 | `%eax`、`%ax`、`%al` | 寄存器中的数据 | 可以 | 可以 |
| 存储器 | `(%edx)`、`8(%ebp)` | 地址所指向的内存数据 | 可以，取决于指令 | 可以，取决于指令 |

`%eax` 表示 EAX 中的数据；`(%eax)` 表示用 EAX 中的值作为地址，访问内存。两者不能混淆。

对于本节的普通 `mov`、`add`、`sub`，常见组合为：

| src → dst | 是否允许 | 例子 |
|------|:------:|------|
| 立即数 → 寄存器 | 允许 | `movl $5, %eax` |
| 立即数 → 内存 | 允许 | `movl $5, (%edx)` |
| 寄存器 → 寄存器 | 允许 | `movl %eax, %ebx` |
| 内存 → 寄存器 | 允许 | `movl (%edx), %eax` |
| 寄存器 → 内存 | 允许 | `movl %eax, (%edx)` |
| 内存 → 内存 | 不允许直接使用 | 需要先读入寄存器，再写入另一处内存 |
| 任意数据 → 立即数 | 不允许 | 立即数是常量，不能接收结果 |

扩展传送 `movs`、`movz` 的源是寄存器或内存，目的必须是更宽的寄存器，源不能是立即数。`lea` 的源写成内存地址表达式，目的为寄存器，但它计算地址而不读取内存。

#### （2）内存地址怎么写

常见格式为：

```text
位移(基址寄存器, 变址寄存器, 比例因子)
```

$$
\text{有效地址}=\text{位移}+\text{基址寄存器的值}+\text{变址寄存器的值}\times\text{比例因子}
$$

| 写法 | 地址如何计算 |
|------|------|
| `(%edx)` | EDX 的值 |
| `8(%ebp)` | EBP 的值 + 8 |
| `-4(%ebp)` | EBP 的值 − 4 |
| `(%ebx,%ecx)` | EBX 的值 + ECX 的值 |
| `(,%ecx,4)` | ECX 的值 × 4 |
| `8(%ebx,%ecx,4)` | EBX 的值 + ECX 的值 × 4 + 8 |
| `0x1000` | 固定地址 `0x1000`，不是立即数；立即数应写 `$0x1000` |

比例因子只能取 1、2、4、8，省略时默认为 1。IA-32 中这里的地址寄存器使用 32 位形式，ESP 不能作为变址寄存器。地址表达式中的逗号位于括号内部，与 src、dst 之间的分隔逗号作用不同。

<span style="color:#c0392b; text-decoration:underline">**地址寄存器的位数不等于内存数据的位数：movb (%edx), %al 用 32 位 EDX 定位内存，但只读取 8 位数据。**</span>

### 5. 常见情况综合示例

以下各个示例独立理解，内存地址均假定有效可访问。

| 情况 | AT&T 指令 | 功能或结果 |
|------|------|------|
| 立即数 → 寄存器 | `movl $5, %eax` | EAX ← 5 |
| 立即数 → 内存 | `movl $5, 8(%ebp)` | 将 32 位整数 5 写入地址 EBP + 8 处 |
| 寄存器 → 寄存器 | `movw %ax, %bx` | 将 AX 的 16 位数据复制到 BX |
| 内存 → 寄存器 | `movb (%edx), %al` | 从 EDX 指向的内存读取 8 位数据到 AL |
| 寄存器 → 内存 | `movl %eax, -4(%ebp)` | 将 EAX 的 32 位数据写入地址 EBP − 4 处 |
| 基址 + 变址 × 比例 + 位移 | `movl 8(%ebx,%ecx,4), %eax` | 从地址 EBX + ECX × 4 + 8 处读取 32 位数据 |
| 符号扩展 | `movsbl %al, %edx` | 若 AL 为 `0x80`，EDX 变为 `0xFFFFFF80`，有符号值仍为 -128 |
| 零扩展 | `movzbl %al, %edx` | 若 AL 为 `0x80`，EDX 变为 `0x00000080`，即 128 |
| 内存数据符号扩展 | `movswl (%ebx), %eax` | 读取 16 位内存数据，符号扩展为 32 位后放入 EAX |
| 加法 | `addl $3, %eax` | EAX ← EAX + 3 |
| 减法 | `subl %ebx, %eax` | EAX ← EAX − EBX |
| 修改内存数据 | `addl $1, (%edx)` | 将 EDX 指向的 32 位内存数据加 1 |
| 单操作数 | `incl %eax`、`decl %eax`、`negl %eax` | 分别将 EAX 加 1、减 1、取负 |
| 交换 | `xchgl %eax, %ebx` | 交换 EAX 和 EBX 的数据 |
| 压栈 | `pushl %eax` | ESP 减 4，再把 EAX 写入新栈顶 |
| 出栈 | `popl %eax` | 把栈顶 32 位数据读入 EAX，再将 ESP 加 4 |
| 计算地址 | `leal 8(%ebx,%ecx,4), %eax` | EAX ← EBX + ECX × 4 + 8，不读取内存 |
| 比较 | `cmpl %ebx, %eax` | 按 EAX − EBX 设置标志，不修改 EAX 和 EBX |
| 条件跳转 | `je label` | 若 ZF = 1，则跳到 label；常用于比较后相等时跳转 |

内存到内存的普通传送需要借助寄存器，例如将 EDX 指向的 32 位数据复制到 ECX 指向的位置：

```asm
movl (%edx), %eax
movl %eax, (%ecx)
```

若 EBP 为 `0x1000`、ECX 为 3，则地址表达式 `8(%ebp,%ecx,4)` 算得 `0x1014`：

```asm
movl 8(%ebp,%ecx,4), %eax   # 取该地址处的数据
leal 8(%ebp,%ecx,4), %eax   # 取地址本身，EAX = 0x1014
```
