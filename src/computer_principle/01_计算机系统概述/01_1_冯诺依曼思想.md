## 1.1.1 冯·诺依曼结构的主要思想

1. 计算机应由<span style="color:#c0392b; text-decoration:underline">**运算器**</span>、<span style="color:#c0392b; text-decoration:underline">**控制器**</span>、<span style="color:#c0392b; text-decoration:underline">**存储器**</span>、<span style="color:#c0392b; text-decoration:underline">**输入设备**</span>和<span style="color:#c0392b; text-decoration:underline">**输出设备**</span>五个基本部件组成。

2. 各基本部件的功能是：

   - <span style="color:#c0392b; text-decoration:underline">**存储器**</span>不仅能存放数据，而且也能存放指令，形式上两者没有区别，但计算机应能区分数据还是指令；

   - <span style="color:#c0392b; text-decoration:underline">**控制器**</span>应能自动取出指令来执行；

   - <span style="color:#c0392b; text-decoration:underline">**运算器**</span>应能进行加/减/乘/除四种基本算术运算，并且也能进行一些逻辑运算和附加运算；

   - 操作人员可以通过<span style="color:#c0392b; text-decoration:underline">**输入设备**</span>、<span style="color:#c0392b; text-decoration:underline">**输出设备**</span>和主机进行通信。

3. 内部以<span style="color:#c0392b; text-decoration:underline">**二进制**</span>表示指令和数据。每条指令由操作码和地址码两部分组成。操作码指出操作类型，地址码指出操作数的地址。由一串指令组成程序。

4. 采用“<span style="color:#c0392b; text-decoration:underline">**存储程序**</span>”工作方式。

## 1.1.3 指令执行过程

一条指令的执行过程分为以下步骤：

1. **取指**：PC的值送到MAR，从存储器中取出指令送到MDR，再送到IR
2. **译码**：控制器对IR中的指令进行译码，确定操作类型
3. **执行**：根据译码结果，控制器发出控制信号，ALU执行相应运算
4. **回写**：将运算结果写回寄存器或存储器

## 1.1.4 指令

### 1. 指令的基本概念

指令就是让 CPU 完成一件事的命令，是 CPU 能够理解并执行的基本单位。

一条指令通常由以下两部分组成：

- <span style="color:#c0392b; text-decoration:underline">**操作码（OP）**</span>：指出 CPU 要执行什么操作，如加、减、读取或存储。
- <span style="color:#c0392b; text-decoration:underline">**地址码（操作数）**</span>：指出参加操作的数据或数据所在的位置。

指令具有<span style="color:#c0392b; text-decoration:underline">**原子性**</span>，即一条指令是 CPU 执行操作时不可再分的基本单位。

**正确解释和执行指令的两个基本条件：**

CPU 要正确解释并执行一条机器指令，必须知道以下两项规定：

1. <span style="color:#c0392b; text-decoration:underline">**指令格式（Instruction Format）**</span>：规定一条指令由哪些字段组成，以及各字段的位置和位数。CPU 据此判断各段二进制位是操作码、寄存器编号、主存地址还是其他信息。
2. <span style="color:#c0392b; text-decoration:underline">**操作码语义（Opcode Semantics）**</span>：规定每个操作码表示什么操作，以及操作数从哪里取得、运算结果保存到哪里。

指令格式解决的是“<span style="color:#c0392b; text-decoration:underline">**各字段如何划分和解释**</span>”的问题，操作码语义解决的是“<span style="color:#c0392b; text-decoration:underline">**CPU 具体执行什么操作**</span>”的问题。二者都是 CPU 对机器指令进行译码和执行的依据。

更完整地说，这些规定属于<span style="color:#c0392b; text-decoration:underline">**指令集体系结构（Instruction Set Architecture，ISA）**</span>。ISA 是软件与硬件之间的机器级接口，除了指令格式和操作码语义外，通常还规定寄存器、数据类型和寻址方式等内容。

### 2. 指令格式与编码

指令在计算机内部使用二进制表示。下面以一条指令占 **8 位**为例，介绍两种指令格式。

| 指令格式 | 二进制结构 | 各字段含义 | 执行功能 |
|----------|------------|------------|----------|
| R 格式 | `op(4位) + rt(2位) + rs(2位)` | `op` 是操作码，`rt` 是目的寄存器地址，`rs` 是源寄存器地址 | `R[rt] ← R[rs]` 或 `R[rt] ← R[rt] op R[rs]` |
| M 格式 | `op(4位) + addr(4位)` | `op` 是操作码，`addr` 是主存地址 | `R[0] ← M[addr]` 或 `M[addr] ← R[0]` |

其中，<span style="color:#c0392b; text-decoration:underline">**R 格式用于寄存器之间的数据传送和运算，M 格式用于 CPU 与主存之间的数据传送**</span>。

#### （1）R 格式（寄存器型指令）

| 操作码 | 指令 | 功能 |
|--------|------|------|
| `0000` | `mov`（传送） | `R[rt] ← R[rs]` |
| `0001` | `add`（加法） | `R[rt] ← R[rt] + R[rs]` |

- `0000 11 01`：`op=0000`，`rt=11₂=3`，`rs=01₂=1`，执行 `R[3] ← R[1]`。
- `0001 00 01`：`op=0001`，`rt=00₂=0`，`rs=01₂=1`，执行 `R[0] ← R[0] + R[1]`。

#### （2）M 格式（访存型指令）

| 操作码 | 指令 | 功能 |
|--------|------|------|
| `1110` | `load`（取数） | `R[0] ← M[addr]` |
| `1111` | `store`（存数） | `M[addr] ← R[0]` |

- `1110 0110`：`op=1110`，`addr=0110₂=6`，从主存地址 6 取数并送入 `R[0]`。
- `1111 1010`：`op=1111`，`addr=1010₂=10`，将 `R[0]` 中的数据存入主存地址 10。

由此可见，同样是 8 位二进制信息，CPU 会先根据<span style="color:#c0392b; text-decoration:underline">**操作码**</span>判断要执行的操作，再按照相应的<span style="color:#c0392b; text-decoration:underline">**指令格式**</span>解释后面的地址码。

### 3. 指令执行实例：计算 `z = x + y`

计算机完成 `z = x + y` 可以分为两个阶段：

| 阶段 | 名称 | 主要工作 |
|------|------|----------|
| 第一阶段 | <span style="color:#c0392b; text-decoration:underline">**程序装入（Loading）**</span> | 把程序的机器指令和需要处理的数据装入主存，为运行程序做好准备 |
| 第二阶段 | <span style="color:#c0392b; text-decoration:underline">**程序执行（Execution）**</span> | CPU 根据 PC 指出的地址逐条取出指令，经过译码后执行这些指令 |

程序装入只是把指令和数据放到主存中，<span style="color:#c0392b; text-decoration:underline">**装入不等于执行**</span>；程序装入完成后，CPU 才开始执行指令。

假设 `x`、`y` 分别存放在主存的 5、6 号单元，运算结果 `z` 存放在 7 号单元：

| 主存地址 | 主存单元内容 | 内容说明 | 汇编指令 |
|----------|--------------|----------|----------|
| 0 | `1110 0110` | `R[0] ← M[6]`，取出 `y` | `load r0, 6#` |
| 1 | `0000 0100` | `R[1] ← R[0]`，暂存 `y` | `mov r1, r0` |
| 2 | `1110 0101` | `R[0] ← M[5]`，取出 `x` | `load r0, 5#` |
| 3 | `0001 0001` | `R[0] ← R[0] + R[1]` | `add r0, r1` |
| 4 | `1111 0111` | `M[7] ← R[0]`，保存结果 | `store 7#, r0` |
| 5 | `0001 0000` | 操作数 `x=16` | — |
| 6 | `0010 0001` | 操作数 `y=33` | — |
| 7 | `0000 0000` | 结果 `z`，初始值为 0 | — |

主存中的这些内容分为指令和数据两类：

| 主存区域 | 内容类型 | CPU 的使用方式 |
|----------|----------|----------------|
| 地址 0～4 | 指令 | CPU 根据 PC 逐条取出并执行 |
| 地址 5 | 数据 `x=16` | `load` 指令将它读入寄存器 |
| 地址 6 | 数据 `y=33` | `load` 指令将它读入寄存器 |
| 地址 7 | 数据 `z=0` | `store` 指令将运算结果写入这里 |

`x=16`、`y=33` 和 `z=0` 表示变量的数值，不是让 CPU 完成某种操作的命令，因此它们<span style="color:#c0392b; text-decoration:underline">**没有操作码，也不需要采用指令格式**</span>。例如，地址 5 中的 `0001 0000` 作为数据解释时表示十进制数 16。

同一串二进制究竟表示指令还是数据，取决于 CPU 的访问方式：CPU 根据 PC 取出的内容被解释为指令；执行 `load` 或 `store` 时访问的内容或位置被解释为数据。

CPU 按照主存地址从 0 到 4 依次执行指令。每条指令的执行又由取指、译码、PC 增量、执行和送结果等<span style="color:#c0392b; text-decoration:underline">**微操作（Micro-operation）**</span>组成：

| 执行步骤 | `1110 0110` | `0000 0100` | `1110 0101` | `0001 0001` | `1111 0111` |
|----------|-------------|-------------|-------------|-------------|-------------|
| 汇编指令 | `load r0, 6#` | `mov r1, r0` | `load r0, 5#` | `add r0, r1` | `store 7#, r0` |
| 取指令 | `IR ← M[0000]` | `IR ← M[0001]` | `IR ← M[0010]` | `IR ← M[0011]` | `IR ← M[0100]` |
| 译码 | 取数 | 传送 | 取数 | 加法 | 存数 |
| PC 增量 | `PC ← 0000+1` | `PC ← 0001+1` | `PC ← 0010+1` | `PC ← 0011+1` | `PC ← 0100+1` |
| 取数、执行 | `MDR ← M[0110]` | `A ← R[0]`，`F ← A` | `MDR ← M[0101]` | `A ← R[0]`，`B ← R[1]`，`F ← A+B` | `MDR ← R[0]` |
| 送结果 | `R[0] ← MDR` | `R[1] ← F` | `R[0] ← MDR` | `R[0] ← F` | `M[0111] ← MDR` |
| 执行结果 | `R[0]=33` | `R[1]=33` | `R[0]=16` | `R[0]=16+33=49` | `M[7]=49` |

表中的 `A`、`B` 表示 ALU 的两个输入，`F` 表示 ALU 的输出；`IR` 保存当前指令，`PC` 指向下一条指令，`MDR` 临时保存从主存读出或准备写入主存的数据。

表中使用 `IR ← M[PC]` 的形式简写取指过程。结合前面的硬件结构，实际的数据传送过程为 `PC → MAR → 主存 → MDR → IR`。

这个例子说明：一条高级语言语句可能需要多条机器指令共同完成；在冯·诺依曼结构中，<span style="color:#c0392b; text-decoration:underline">**指令和数据都以二进制形式存放在主存中，CPU 按照“取指、译码、执行”的过程逐条执行指令**</span>。

## 1.1.5 程序的编译过程

### 1. 翻译程序的三种类型

把源程序转换成机器可执行的程序的程序统称为<span style="color:#c0392b; text-decoration:underline">**翻译程序**</span>，按翻译方式不同分为三种：

| 类型 | 别称 | 主要特点 | 典型例子 |
|------|------|----------|----------|
| <span style="color:#c0392b; text-decoration:underline">**解释器**</span> | 解释程序 | 读入一句源程序就翻译并执行一句，<span style="color:#c0392b; text-decoration:underline">**不生成目标文件**</span>，边解释边执行 | 解释方式执行的高级语言程序 |
| <span style="color:#c0392b; text-decoration:underline">**编译器**</span> | 编译程序 | 把整个源程序翻译成用汇编语言或机器语言表示的目标程序，生成目标文件 | C 语言编译器 `cc1` |
| <span style="color:#c0392b; text-decoration:underline">**汇编器**</span> | 汇编程序 | 把汇编语言源程序翻译成二进制机器指令（目标代码） | 汇编器 `as` |

### 2. 从源程序到可执行文件

用高级语言编写的源程序（如 `hello.c`）不能直接被 CPU 执行，必须经过一系列转换，变成 <span style="color:#c0392b; text-decoration:underline">**二进制机器指令**</span>。完整的转换依次经过<span style="color:#c0392b; text-decoration:underline">**预处理、编译、汇编、链接**</span>四个阶段，每个阶段都由一个独立的处理程序完成，上一阶段的处理结果就是下一阶段的输入。

| 阶段 | 处理程序 | 处理结果（扩展名） | 主要工作 |
|------|----------|--------------------|----------|
| 预处理阶段 | <span style="color:#c0392b; text-decoration:underline">**预处理器**</span> `cpp` | 源程序 `hello.i`（`.i`） | 展开 `#include` 头文件、替换 `#define` 宏、删除注释，仍是高级语言 |
| 编译阶段 | <span style="color:#c0392b; text-decoration:underline">**编译器**</span> `cc1` | 汇编源程序 `hello.s`（`.s`） | 词法分析、语法分析、语义分析和优化，把高级语言<span style="color:#c0392b; text-decoration:underline">**翻译成汇编语言**</span> |
| 汇编阶段 | <span style="color:#c0392b; text-decoration:underline">**汇编器**</span> `as` | 可重定位目标文件（二进制）`hello.o`（`.o`） | 把汇编指令<span style="color:#c0392b; text-decoration:underline">**翻译成二进制机器指令**</span>（目标代码） |
| 链接阶段 | <span style="color:#c0392b; text-decoration:underline">**链接器**</span> `ld` | 可执行文件（二进制）`hello` | 合并 `hello.o` 和 `printf.o` 等目标文件，分配统一主存地址，<span style="color:#c0392b; text-decoration:underline">**解决符号引用**</span> |

### 3. 编译过程的完整流程

以 GCC 编译 `hello.c` 为例（`printf` 函数定义在单独的目标文件 `printf.o` 中）：

### 4. 两种目标文件的区别

| 类型 | 示例 | 说明 |
|------|------|------|
| <span style="color:#c0392b; text-decoration:underline">**可重定位目标文件**</span> | `hello.o` | 代码和数据尚未确定在主存中的存放地址，不能直接执行，等待链接器重新定位 |
| <span style="color:#c0392b; text-decoration:underline">**可执行目标文件**</span> | `hello` | 链接器完成地址分配和符号解析后生成的完整二进制映像，可以直接装入主存由 CPU 执行 |

`hello.c` 中调用的 `printf` 函数并不在 `hello.o` 里，链接器在链接阶段把 `printf.o` 一并合并进来，才能得到完整的可执行文件 `hello`。因此<span style="color:#c0392b; text-decoration:underline">**汇编阶段结束得到的还只是目标文件，必须经过链接才能执行**</span>。

### 5. 可执行文件的启动和执行

链接生成的可执行文件 `hello` 平时存放在<span style="color:#c0392b; text-decoration:underline">**磁盘**</span>上，运行时要先<span style="color:#c0392b; text-decoration:underline">**装入主存**</span>，再由 CPU 逐条取出指令执行。整个过程由 CPU、主存、磁盘、键盘、显示器等部件在<span style="color:#c0392b; text-decoration:underline">**处理器总线、存储器总线、I/O 总线**</span>的连接下协同完成（对应教材图 1.9）：

```mermaid
flowchart TB
    subgraph CPU["CPU"]
        direction LR
        CTRL["控制器"] --- REG["寄存器堆"]
        REG <--> ALU["ALU"]
        REG <--> BI["总线接口"]
    end

    BI <-->|"处理器总线"| BR["总线桥"]
    BR <-->|"② 指令、数据<br/>经存储器总线传送"| MEM["主存储器<br/>“./hello”<br/>“hello, world”"]
    IOB["I/O 总线"]
    IOB <-->|"④ 程序、数据<br/>经存储器总线装入主存"| BR

    IOB <-->|"① 键入 ./hello"| USB["USB 控制器<br/>鼠标、键盘"]
    IOB <-->|"③ 读取 hello 可执行文件"| DISKC["磁盘控制器<br/>磁盘<br/>hello 可执行文件"]
    IOB -->|"⑤ 显示输出"| DISP["显示适配卡<br/>显示器<br/>hello, world"]

    classDef cpu fill:#eff6ff,stroke:#2563eb,stroke-width:2px,color:#111827;
    classDef mem fill:#fff7ed,stroke:#9a3412,stroke-width:2px,color:#111827;
```

说明（对应图中编号）：

1. **① 输入命令**：用户在键盘键入 `./hello`，字符经 USB 控制器、I/O 总线送入主存，shell 读到该命令。
2. **③④ 装入程序**：shell 找到磁盘上的 `hello` 可执行文件，经磁盘控制器、I/O 总线、存储器总线把它<span style="color:#c0392b; text-decoration:underline">**装入主存**</span>。
3. **② 取指执行**：操作系统把 `hello` 第一条指令地址送入 PC，CPU 经处理器总线、存储器总线从主存取指令，按“取指、译码、执行”逐条执行指令。
4. **⑤ 显示输出**：`printf` 要输出的 `hello, world` 从主存经 I/O 总线送显示适配卡，在显示器上显示。

<span style="color:#c0392b; text-decoration:underline">**装入不等于执行**</span>，且执行期间<span style="color:#c0392b; text-decoration:underline">**指令和数据始终存放在主存中**</span>，CPU 通过总线反复访问主存，体现了冯·诺依曼结构的“存储程序”思想。
