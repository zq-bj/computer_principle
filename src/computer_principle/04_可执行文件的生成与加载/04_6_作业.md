## 4.6.2 符号表分析题

### 1. 题目（第 30 页，原题 4）

程序有 main.c 和 swap.c 两个源文件。

```c
/* main.c */
extern void swap();
int buf[2] = {1, 2};
int main() {
    swap();
    return 0;
}
```

```c
/* swap.c */
extern int buf[];
int *bufp0 = &buf[0];
int *bufp1;

static void incr() {
    static int count = 0;
    count++;
}

void swap() {
    int temp;
    incr();
    bufp1 = &buf[1];
    temp = *bufp0;
    *bufp0 = *bufp1;
    *bufp1 = temp;
}
```

<details class="example-answer">
<summary>答案</summary>

- **类型看符号是什么**：本模块定义的变量为 OBJECT，定义的函数为 FUNC；图中的外部引用 `swap`、`buf` 记为 NOTYPE。

## 4.6.5 指令流水线例题

### 例题2：串行执行与流水线执行时间

设译码时间为 60，存储器读写为 200，PC+1 为 40，寄存器读写为 50，ALU 为 100。分别计算串行执行和流水线执行下列指令的时间：

```asm
add r0, r1
mov r1, r0
load r0, 6#
store 8#, r0
```

课件未标出这些数值的时间单位，按题给统一单位分析。

<details class="example-answer">
<summary>答案</summary>

先根据指令确定实际经过的操作，再判断哪些操作能同时进行。

- `add`：取指、译码与读寄存器、ALU 加法、写回寄存器。
- `mov`：取指、译码与读寄存器、寄存器数据传送与写回。
- `load`：取指、译码与地址准备、读取数据存储器、写回寄存器。
- `store`：取指、译码与地址及数据准备、写数据存储器。

串行执行总时间为各条指令所需操作时间之和。同一阶段允许并行的操作取最大值，必须先后完成的操作相加。

对于 k 段、各段用时分别为 $t_1,\ldots,t_k$ 的同步流水线，时钟周期至少为 $\tau=\max(t_1,\ldots,t_k)$。在无停顿、每条指令都占用 k 个阶段的理想情况下，n 条指令总时间为：

$$
T_{\text{流水}}=(k+n-1)\tau
$$

本题有 4 条指令，若采用本章四段流水线，则理想时间为 $7\tau$。若 IF 中取指与 PC 更新并行，ID 中译码与寄存器读取并行，EX 中 ALU 与数据访存按指令择一，WB 写寄存器，则各段用时为 200、60、200、50，$\tau=200$，理想流水时间为 1400（题给时间单位）。

上述 1400 依赖这些假设。题目片段未说明取指和数据访存是否争用存储器、相邻指令依赖是否需要停顿，以及有效地址计算是否额外占时；实际串行时间和有停顿的流水时间需结合课件的数据通路与相关处理规则确定，不能把理想流水时间直接当成唯一结果。

</details>

## 4.6.6 同名符号解析例题

### 例题3：两个强符号同名

```c
/* main.c */
int x = 10;
int y;
int p1(void);
int main() {
    x = p1();
    return x;
}
```

```c
/* p1.c */
int x = 20;
int y = 0;
int p1() {
    return x;
}
```

判断程序能否成功链接，并说明原因。

<details class="example-answer">
<summary>答案</summary>

不能成功链接。`main.c` 中的 `int x = 10` 和 `p1.c` 中的 `int x = 20` 都是强符号定义，同名强符号不能重复定义，因此链接报错。

按课件的 COMMON 模型，`main.c` 中的 `int y` 是 COMMON 符号，`p1.c` 中的 `int y = 0` 是强符号，`y` 以强符号定义为准；这不能消除 `x` 重复定义导致的错误。

</details>

### 例题4：同名变量的类型不一致

```c
/* main.c */
#include <stdio.h>
int y = 100, z;
void p1(void);
int main() {
    z = 1000;
    p1();
    printf("y=%d,z=%d\n", y, z);
    return 0;
}
```

```c
/* p1.c */
int y;
short z;
void p1() {
    y = 200;
    z = 2000;
}
```

按课件的 COMMON 模型，分析同名符号如何关联，以及变量类型不一致会带来什么问题。

<details class="example-answer">
<summary>答案</summary>

- `y`：`main.c` 中的 `int y = 100` 是强符号，`p1.c` 中的 `int y` 是 COMMON 符号。两模块中的 `y` 关联到强符号定义，调用 `p1()` 后该存储位置被写入 200。
- `z`：两个模块中的 `z` 都按 COMMON 处理，但一个声明为 `int`，另一个为 `short`。按课件规则，链接器按较大的空间分配；两模块的访问宽度仍分别由各自的声明决定。
- `main()` 先按 `int` 写入 1000，`p1()` 再按 `short` 写入 2000，后者只覆盖该存储空间的一部分。具体读回结果受类型宽度、字节序等条件影响；跨模块类型不一致不符合 C 的类型兼容要求，不能据此给出可移植的确定输出。

若使用 `-fno-common`，这些未初始化全局变量通常直接形成 `.bss` 中的定义，重复定义可能导致链接报错，应按题目指定的编译模型分析。

</details>
