## 5.4.1 主存块的替换算法

### 1. 替换发生的条件

当所需主存块需要装入 Cache，而允许放置的位置均已占用时，需要选择替换对象。直接映射只有固定一行；全相联、组相联需要在允许的范围内选择。

### 2. 课件列出的算法

| 算法 | 选择原则 |
|------|----------|
| FIFO，先进先出 | 替换最早进入的块 |
| LRU，最近最少使用 | 替换距最近一次访问最久的块 |
| 最不经常使用 | 替换访问次数较少的块 |
| 随机替换 | 随机选择允许替换的块 |

## 5.4.2 Cache 的写策略

**写命中（Write Hit）**：CPU 要写的数据，在 Cache 中**已经有对应的块**，即写操作“命中”了 Cache。

**写缺失（Write Miss）**：CPU 要写的数据，在 Cache 中**没有对应的块**，即写操作“没命中”。

这两个概念是下面几种写策略的分类依据。

### 1. 写命中时怎么处理（决定“通写法”还是“回写法”）

- **通写法（写直达）**：数据同时写入 Cache 和主存，两边始终一致。缺点是每次写都要访问慢速主存。
- **回写法（写回）**：只写 Cache，并给该块打上“脏位（dirty bit）”标记；等这个块被替换出去时，才一次性写回主存。写得快，但 Cache 与主存暂时不一致。

### 2. 写缺失时怎么处理（决定“写分配”还是“非写分配”）

- **写分配法**：先把主存中该数据所在的块调入 Cache，然后再在 Cache 中修改。利用了局部性原理，后续再访问同一块时能命中。
- **非写分配法**：不调入 Cache，直接把数据写到主存。

### 3. 常见搭配

| 写命中策略 | 写缺失策略 |
|------|------|
| 通写法 | 非写分配法 |
| 回写法 | 写分配法 |

原因：通写法每次都会写主存，所以缺失时直接写主存，不必调块进来；回写法依赖 Cache 暂存修改，所以缺失时要先把块调入 Cache，才能“只写 Cache”。
